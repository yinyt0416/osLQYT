# Pin/ASan 兼容性排查

目前未解决，40 条不兼容记录继续保留，不计为有效测量。

涉及 doubleFree、CB_stringbuffer 的 IPB/IDB，各配置 10 次。

## 本次验证

- 在独立目录 `/home/sct/rq3-compat-clang35` 测试，不覆盖正式批次。
- 原 GCC 4.8 ASan：doubleFree 的 IPB 短测试（repeat=101，预算10，限时30秒）记录了4次工具错误，没有有效完成调用。程序退出时 `libdl` 中出现 ASan 的非法释放报告。
- 安装 Clang 3.5，保留 `-fsanitize=address`，对两个原始程序重新编译，并以 root 运行 Pin 的 race profiler 和 systematic controller。仍出现 `C:Tool (or Pin) caused signal 11`，部分调用超时。
- 新编译器探测与正式 GCC 数据不合并；编译成功或生成 race.db 不代表受控搜索成功。
- 历史 preparation JSON 中可能出现 READY，这是脚本只检查 race.db 是否存在造成的，不能据此覆盖正式不兼容记录。

## 后续可行方向

需要验证其他 Pin/Maple/ASan 版本组合，或修复 Maple 与 ASan 的插桩交互。任何新组合都需要先通过“正确程序不误报、已知错误可检出”的对照验证，然后重新测量该环境下的 native 和工具时间。

关闭 ASan 或修改程序使错误消失，不能作为兼容性修复。现阶段不承诺一定能获得这40条有效数据。

原始验证日志与独立探测程序见 `rq3-compat-diagnostics.tar.gz`。此次排查不改变 rq3_overhead.csv 的正式结果。
